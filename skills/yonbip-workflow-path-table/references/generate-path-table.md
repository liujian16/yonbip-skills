# 生成路径表

## 核心原则

### 动态列提取

**不要假设固定的列**，每个表格结构都必须从用户的描述中提取：

1. **条件列**: 提取所有提到的条件维度（费用类型、金额、供应商类型等）
   - **列名要反映业务语义**：如描述"合同审批"，条件列应命名为"文件类型"或"业务类型"，而非默认"费用类型"
   - **值要简洁明确**：如"合同审批"场景，条件值应为"合同"，而非把场景名直接作为值
2. **角色列**: 提取审批链中提到的所有角色（部门主管、财务经理等）
3. **仅根据描述中的实际内容构建表格结构**

**常见条件列命名模式**：
| 场景关键词 | 推荐条件列名 |
|-----------|------------|
| 费用、报销、招待、差旅 | 费用类型 |
| 合同、协议、文件 | 文件类型 / 业务类型 |
| 采购、物资、办公用品 | 采购类别 |
| 借款、申请、入职 | 流程类型 / 申请类型 |

### 条件互斥

**每一行的条件组合必须是唯一的、互斥的**。任意给定输入只能匹配唯一一行。

#### 互斥规则

1. **同一列的值必须互斥**: `< 1000` 和 `>= 1000` 互斥；`全部` 和 `>= 5000` 重叠
2. **行组合必须互斥**: 即使单列值不互斥，组合后也必须互斥
3. **使用分区而非叠加**: 不要用"全部"叠加更具体的条件

#### 金额区间标准分区

```
< 1000           →  小于1000
[1000, 5000)     →  1000到5000以下
>= 5000          →  5000及以上
```

#### 去除冗余

如果某一个条件列的值是相同的，那么这个条件列就没有必要。

#### 常见错误

##### 条件重叠

```
| 采购类别 | 金额 |
| 行政类采购 | 全部   | ← 与下一行重叠
| 行政类采购 | >= 5000 |
```

##### 互斥分区（正确）

```
| 采购类别 | 金额 |
| 行政类采购 | < 5000  |
| 行政类采购 | >= 5000 |
```

## 步骤

### 1.0 理解与澄清

**试运行模式下跳过**: 如果设置了 `--dryrun` 参数，跳过此步骤。

接收到用户的审批规则后，首先分析内容：

1. **理解**: 解析自然语言并识别：
   - 主要业务场景（费用类型、采购类型等）
   - 关键条件（金额区间、供应商类型等）
   - 审批角色及其顺序

2. **检查歧义**: 确定规则是否完整且无歧义：
   - 条件覆盖不完整（是否有遗漏的场景？）
   - 角色定义不明确（角色名称是否明确？）
   - 边界条件未指定（边界值如何处理？）

3. **决策点**:
   - **如果规则清晰**: 直接跳到步骤 1.1
   - **如果存在歧义**: 使用 AskUserQuestion 澄清

**需要澄清的典型场景**：

| 场景 | 规则示例 | 问题示例 |
|-----|---------|---------|
| 条件覆盖不完整 | "1000元以下走A，5000元以上走B" | "1000-5000元之间如何处理？" |
| 角色不明确 | "主管审批" | "是部门主管还是业务主管？" |
| 边界值歧义 | "1000元以下"和"1000-5000元" | "正好1000元走哪条路径？" |
| 兜底规则缺失 | 只说明了特定场景 | "其他未说明的场景如何处理？" |

### 1.1 提取与结构化

分析自然语言并识别：

**A. 所有条件维度（前几列）**
- 哪些类别/维度决定审批路径？
- 常见模式：费用类型、金额区间、供应商性质、部门类型等

**B. 所有审批角色（后几列）**
- 审批人是谁？列出提到的所有唯一角色
- 保留描述中的确切角色名称
- 不要添加未提及的角色

**C. 审批逻辑（表格内容）**
- 使用数字（1、2、3...）表示审批顺序
- 使用 `n/a` 表示不参与的角色
- 使用 `N:[条件]` 表示有条件的审批

### 1.2 生成Markdown表格

```
| [条件列1] | [条件列2] | ... | [角色1] | [角色2] | [角色3] | ... |
|----------|----------|-----|---------|---------|---------|-----|
| 值A      | 条件X    | ... | 1       | n/a     | 2       | ... |
```

**展示前验证互斥性**: 检查没有两行有重叠的条件。

### 1.3 用户确认

询问："请确认以上流程路径表是否正确？如需修改请直接告诉我。"

### 1.4 生成Excel

```bash
python3 ${SKILL_DIR}/scripts/md_to_excel.py <input.md> <output.xlsx> --condition-cols <N>
```

## 格式规范

### 金额区间格式

| 格式 | 含义 | 示例 |
|------|------|------|
| `< X` | 小于 X | `< 5000` |
| `<= X` | 小于等于 X | `<= 10000` |
| `> X` | 大于 X | `> 200` |
| `>= X` | 大于等于 X | `>= 10000` |
| `[X, Y)` | X ≤ 金额 < Y（半开区间） | `[5000, 10000)` |
| `(X, Y]` | X < 金额 ≤ Y | `(5000, 10000]` |
| `[X, Y]` | X ≤ 金额 ≤ Y（闭区间） | `[5000, 10000]` |
| `全部` | 所有金额 | `全部` |

**注**: YonBIP 标准优先使用半开区间 `[X, Y)`。

### 审批节点

- **1、2、3...**: 审批顺序
- **n/a**: 角色不参与
- **N:[条件]**: 第N步有额外条件（如 `2:[金额>=500]` 表示第2步且要求金额 ≥ 500）

### 自然语言映射

#### 阈值短语

| 短语 | 格式 |
|------|------|
| X元以下 | `< X` |
| X元以内 | `<= X` |
| X-Y元 | `[X, Y)` |
| X元以上 | `>= X` |
| 大于X元 | `> X` |
| 大于等于X元 | `>= X` |
| 小于X元 | `< X` |
| 所有金额/全部 | `全部` |

#### 角色名称规范化

| 输入变体 | 标准名 |
|---------|--------|
| 主管, 业务主管 | 业务主管 |
| 经理, 业务经理 | 业务经理 |
| 总经理, 业务总经理 | 业务总经理 |
| 财务, 财务专员 | 财务专员 |
| 财务经理 | 财务经理 |
| 总裁, 董事长 | 总裁 |

#### 链式短语

| 短语 | 解释 |
|------|------|
| 走A和B | A 然后 B（顺序） |
| 增加 C | 将 C 添加到现有链 |
| 全审/全部 | 所有角色参与 |
| 同时/并列 | 并行审批（使用相同编号） |
| C环节需满足X | C 有条件 X |

## 示例

### 示例1：招待费（简单场景）

**输入**:
```
招待费审批规则：1000元以下只需部门主管审批；1000-5000元需要部门主管和财务经理；5000元以上则需要部门主管、财务经理和总经理。
```

**输出**:
| 费用类型 | 金额 | 部门主管 | 财务经理 | 总经理 |
|---------|------|---------|---------|--------|
| 招待费 | < 1000 | 1 | n/a | n/a |
| 招待费 | [1000, 5000) | 1 | 2 | n/a |
| 招待费 | >= 5000 | 1 | 2 | 3 |

### 示例2：采购审批（多条件+多角色）

**输入**:
```
行政类采购：无论金额，部门负责人→行政主管。超过5000元增加财务总监。
生产类采购：<20000：部门负责人→采购专员→财务总监。≥20000：部门负责人→采购经理→财务总监→总经理。新合作方需增加法律顾问。
```

**输出**:
| 采购类别 | 金额 | 供应商类型 | 部门负责人 | 行政主管 | 采购专员 | 采购经理 | 财务总监 | 总经理 | 法律顾问 |
|---------|------|-----------|-----------|---------|---------|---------|---------|--------|---------|
| 行政类采购 | < 5000 | 全部 | 1 | 2 | n/a | n/a | n/a | n/a | n/a |
| 行政类采购 | >= 5000 | 全部 | 1 | 2 | n/a | n/a | 3 | n/a | n/a |
| 生产类采购 | < 20000 | 全部 | 1 | n/a | 2 | n/a | 3 | n/a | n/a |
| 生产类采购 | >= 20000 | 老合作方 | 1 | n/a | n/a | 2 | 3 | 4 | n/a |
| 生产类采购 | >= 20000 | 新合作方 | 1 | n/a | n/a | 2 | 3 | 4 | 5 |
